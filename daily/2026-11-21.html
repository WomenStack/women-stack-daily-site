Thinking Machines Lab — Inkling 2 Mini：能在笔记本上跑的开源权重循环 Transformer

Thinking Machines Lab — Inkling 2 Mini: an open-weights looped transformer that runs on a laptop

Thinking Machines Lab 于 2026-11-20 发布 Inkling 2 Mini，一个小到能在笔记本上运行的开源权重模型。这是一个混合专家循环 Transformer，总参数 264 亿、每 token 激活 34 亿：中间 12 层每个 token 跑三遍，因此无需写出更多思维链就能推理更久。它在 DeepSWE v1.1（48.2%）和 Vals Index v2.2（46.5%）上领先所有总参数低于 1000 亿的开源权重模型，上下文窗口 100 万 token，内存占用约 20GB；团队演示它在 MacBook Pro 上离线几分钟做出一个可玩的飞行模拟器。以 Apache 2.0 协议发布，上线 Hugging Face 与公司自家的 Tinker 平台，同时发布一个可变循环的研究模型，供研究思维链可监测性。

Thinking Machines Lab released Inkling 2 Mini on 2026-11-20, an open-weights model small enough to run on a laptop. It is a mixture-of-experts looped transformer with 26.4B total parameters and 3.4B active per token: its 12 middle layers run three times for every token, so it reasons longer without writing more chain of thought. It leads every open-weights model under 100B total parameters on DeepSWE v1.1 (48.2%) and Vals Index v2.2 (46.5%), with a 1M-token context window and a ~20GB memory footprint; the team demoed it building a playable flight simulator offline on a MacBook Pro. It is released under Apache 2.0, on Hugging Face and the company's Tinker platform, alongside a variable-loop research model for studying chain-of-thought monitorability.

OpenAI — Performance Factory：Codex agent 让 ChatGPT 保持快速

OpenAI — Performance Factory: Codex agents keep ChatGPT fast

OpenAI 于 2026-11-19 介绍内部系统 Performance Factory：Codex agent 负责调查 ChatGPT 性能回退、提出修复并验证恢复情况，工程师保留每次合并的最终决定权。告警触发后，Regression Workflow 打开一个任务；agent 用共享的 perf-forensics 技能调查，另一个 Codex 会话以对抗方式挑战诊断结论，修复部署后又有 agent 检查性能是否回到基线。三个多月里它跟踪了 1700 多次调查，定位了 600 多个根因——平均每天 17 次自动调查。在人工抽查的 100 条根因建议中，70% 被评为准确；约 400 个修复提议中，15 个以 Codex 原样撰写的 PR 形式上线。OpenAI 表示这套模式——任务服务、分发循环、云端 Codex 执行、事件订阅——可以复用到其他重复性工程工作上。

OpenAI described its Performance Factory on 2026-11-19, an internal system in which Codex agents investigate ChatGPT performance regressions, propose fixes and verify recovery, with engineers keeping final approval on every merge. When an alert fires, the Regression Workflow opens a task; an agent investigates with a shared perf-forensics skill, a separate Codex session adversarially challenges the diagnosis, and after deployment another agent checks performance returned to baseline. In just over three months it tracked more than 1,700 investigations and root-caused over 600 cases — about 17 automated investigations a day. In a manual review of 100 root-cause suggestions, 70% were graded accurate; of roughly 400 proposed fixes, 15 shipped as exact Codex-authored pull requests. OpenAI says the pattern — task service, dispatch loop, cloud Codex execution, event subscriptions — can be reused for other recurring engineering work.

谷歌 — Mirror Dimension：一个合成互联网，用来测试 Chrome 的浏览 agent

Google — Mirror Dimension: a synthetic internet to test Chrome's browsing agents

谷歌 Chrome 安全团队于 2026-11-19 介绍 Mirror Dimension，一个与世隔绝的合成版互联网，用于测试其 auto-browse agent，而不触碰真实网站或账号。Agent 访问真实 URL，但隔离的 gVisor 沙箱中的无头 Chrome 会把流量截获并路由到本地代理，由代理提供生成的网站，同时即时签发 TLS 叶证书并链回预装的自定义根 CA，让浏览器正常验证。一个多 agent 搭建系统——研究、构建与评审 agent 通过 Chrome DevTools for Agents 驱动——建成数千个模拟网站，从商店到银行后台。该沙箱同时也是一个动态红队靶场，可针对间接提示注入做测试，把攻击载荷藏在 HTTP 头里，让被测 agent 看不到异常 URL；自动化管线现在每位安全工程师每天能产出 1000 多个攻击测试候选，是人工的 30 倍以上。

Google's Chrome security team described Mirror Dimension on 2026-11-19, a hermetic synthetic version of the web for testing its auto-browse agents without touching real sites or accounts. Agents navigate to real URLs, but a headless Chrome in an isolated gVisor sandbox routes traffic to a local proxy serving generated sites, with TLS certificates minted on the fly against a custom root CA so the browser validates them normally. A multi-agent harness — research, builder and critic agents driving Chrome DevTools for Agents — builds the thousands of simulated sites, from shops to banking dashboards. The sandbox doubles as a dynamic red-teaming range for indirect prompt injection, hiding payloads in an HTTP header so agents cannot spot the test; the automated pipeline now produces more than 1,000 attack-test candidates a day per security engineer, over 30x what one engineer could do by hand.

Cognition / AWS — Devin 如何在云端 Mac 上跑 macOS 会话

Cognition / AWS — How Devin runs macOS sessions on cloud Macs

AWS 于 2026-11-19 详解 Cognition 如何让 Devin 这位 AI 软件工程师拥有一台 Mac 来构建与测试苹果应用：Devin 会话运行在横跨 6 个 AWS 区域的 Amazon EC2 Mac 裸金属实例上，每个会话启动一个全新的 macOS 虚拟机，不到一分钟就绪。受苹果许可限制，每台物理主机只能运行 2 个隔离的 macOS 虚拟机，且主机最短租用 24 小时——因此会话闲置时，Cognition 会把磁盘状态存为快照并释放虚拟机，之后几秒内从快照恢复；约 90% 的会话在闲置时释放 Mac。Devin 在 Xcode 中构建应用，在 iOS 模拟器中运行，并通过无障碍树操作界面。Cognition 于 2026-09-15 上线 macOS 支持，称 6 周内已有近 1000 家机构使用。

AWS detailed on 2026-11-19 how Cognition gives Devin, its AI software engineer, a Mac to build and test Apple apps: Devin sessions run on Amazon EC2 Mac bare-metal instances across six AWS regions, with a fresh macOS virtual machine started per session in under a minute. Each physical host can run only two isolated macOS VMs under Apple's licensing, and hosts carry a 24-hour minimum allocation — so when a session goes idle, Cognition saves its disk state as a snapshot and releases the VM, resuming from the snapshot in seconds; about 90% of sessions release their Mac when idle. Devin builds the app in Xcode, runs it in the iOS Simulator and drives the interface via the accessibility tree. Cognition launched macOS support on 2026-09-15 and says nearly 1,000 organisations used it within six weeks.

Scott Aaronson's reaction to the claimed Generalized Riemann Hypothesis proof, read in full.
