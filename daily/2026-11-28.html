DeepMind 让 AI 智能体掌控部分算力，为下一代 Gemini 做实验（2026-11-25）

DeepMind lets AI agents control part of its compute for Gemini experiments (2026-11-25)

谷歌 DeepMind 研究副总裁、Gemini 开发负责人 Koray Kavukcuoglu 在公司播客中表示，AI 智能体现在掌控实验室部分算力，自行为下一代 Gemini 模型运行实验。实验室已从 AlphaFold、核聚变等专项团队转向单一通用算法同时服务科研与产品，每一代 Gemini 都是手工打造的一次性系统。作为安全措施，DeepMind 在训练中有意不奖励智能体的思维链（Chain of Thought），使其推理保持未经过滤、可用自然语言在行动前接受审查。Kavukcuoglu 表示，完全的递归自我改进仍然遥远；智能体掌控的算力占比未披露。

Google DeepMind VP of Research Koray Kavukcuoglu, who leads Gemini development, said on a company podcast that AI agents now control part of the lab's compute to run experiments for upcoming Gemini models. The lab has shifted from separate teams for specialized projects like AlphaFold and nuclear fusion to a single general-purpose algorithm for both science and products, and each Gemini generation is a hand-built one-off rather than a fixed architecture. As a safety measure, DeepMind deliberately does not reward the agents' chains of thought during training, so their reasoning stays reviewable in natural language before they act. Kavukcuoglu said full recursive self-improvement remains far off; the share of compute agents control was not disclosed.

谷歌 Workspace MCP 服务器与 CLI 正式发布；2027 年 2 月 1 日起 AI 智能体必须经此接入（2026-11-24）

Google makes Workspace MCP servers and CLI generally available; AI agents must use them from February 1, 2027 (2026-11-24)

谷歌于 11 月 24 日正式发布 8 个托管式 Workspace MCP 服务器（Gmail、Drive、Docs、Sheets、Slides、Calendar、Chat、Tasks）与官方 Workspace CLI（gwscli），同时推出标准版与扩展版两档用量层级和新的 Workspace AI 工具附加条款。自 2027 年 2 月 1 日起，AI 智能体必须通过 MCP 服务器或 CLI 访问 Workspace 数据，而不能直接调用 REST API；继续直连 REST API 的智能体将被限制在标准版配额内，扩展版计费从 2027 年 4 月 1 日开始。附加条款还规定，源自 Workspace API 的数据存储不得超过 30 天，且不得用于模型训练。独立测试者发现，公开的 Gmail 服务器可以搜索、阅读和起草邮件，但不能发送、回复或转发——这些工具仅限合作伙伴，不过谷歌自己的参考页面此后已列出发送工具，具体边界仍在变化中。

Google made its eight hosted Workspace MCP servers (Gmail, Drive, Docs, Sheets, Slides, Calendar, Chat and Tasks) and the official Workspace CLI (gwscli) generally available on November 24, alongside standardized Standard and Scaled usage tiers and a new Workspace AI Tools Addendum. From February 1, 2027, AI agents must reach Workspace data through the MCP servers or the CLI rather than calling REST APIs directly; agents that keep calling the REST APIs will be throttled to Standard-tier quotas, and Scaled-tier billing begins April 1, 2027. The addendum also caps storage of data derived from Workspace APIs at 30 days and bans using it for model training. Independent testers found the public Gmail server can search, read and draft but not send, reply or forward — those tools are partner-only — though Google's own reference page has since listed send tools, so the exact boundary is still shifting.

OpenAI：GPT-6 模型能设计蛋白质，实验室验证在五个靶点上结合成功（2026-11-24）

OpenAI: GPT-6 models can design proteins, with lab-verified binding on five targets (2026-11-24)

OpenAI 称，其 GPT-6 模型仅凭推理和通用代码就能设计新的蛋白质结构与氨基酸序列，无需经由专用生物模型生成设计。在与合作实验室 Onava 的测试中，GPT-6.2 设计的 322 个迷你结合蛋白（minibinder）中有 35 个（10.9%）与目标结合，五个靶点（PD-L1、IL-7Rα、TrkA、VEGF-A、IL-17A）全部至少命中一个；重新设计的抗体结合环在 66–70% 的情况下保留了结合能力。一个内部研究模型在 14 项蛋白质任务中的多项上达到或超过了专用模型，但完整结构预测仍是明显短板，且序列提供与候选筛选仍需专用模型。预印本：《GPT-6 as a Universal Foundation Model for Protein Biology》。

OpenAI reports its GPT-6 models can design new protein structures and amino-acid sequences using only reasoning and general-purpose code, without routing through specialized biology models. In lab tests with partner Onava, 35 of 322 GPT-6.2-designed minibinders (10.9%) bound their intended targets, with at least one hit on all five targets (PD-L1, IL-7Rα, TrkA, VEGF-A, IL-17A); redesigned antibody loops retained binding in 66–70% of cases. An internal research model matched or beat specialized models on many of 14 protein tasks, but full structure prediction remained a clear weakness, and specialized models were still needed to supply sequences and select candidates. Preprint: "GPT-6 as a Universal Foundation Model for Protein Biology".

Anthropic 把 Messages API 迁移到 Rust：CPU 占用减少约 70%，首 token 快 20%（2026-11-25）

Anthropic migrates its Messages API to Rust: about 70% less CPU, 20% faster first token (2026-11-25)

Anthropic 公布了将 Messages API——Claude API、Claude Code 与 Cowork 背后的通道——从 Python 迁移到 Rust 的过程：Claude 约用一周写出核心请求路径的首版，到 2026 年 5 月，Claude 已写出 Anthropic 合并代码的 80% 以上。真正的难点不是生成而是验证：团队把生产环境 API 本身变成验证器，对线上流量做影子测试，逐步比对提示词构建过程（检查点机制），按指纹归类差异，再由 Claude 智能体在内层、外层与记忆三层循环中修复差异。生产流量已于 2026 年 9 月切到 Rust：每请求 CPU 占用减少约 70%，内存减少 80% 以上，首 token 中位时间缩短约 20%——全程零停机、功能开发未冻结。API 流量自 2024 年初至 2026 年秋季增长了约 1,800 倍。

Anthropic published how it migrated its Messages API — the path behind the Claude API, Claude Code and Cowork — from Python to Rust, with Claude writing the first version of the core request path in about a week and, by May 2026, writing more than 80% of the code Anthropic merged. The hard part was verification, not generation: the team turned the production API into an oracle, shadowing live traffic, comparing prompt construction step by step (checkpointing) and grouping mismatches by fingerprint, with Claude agents fixing diffs in nested inner, outer and memory loops. Public traffic moved to Rust in September 2026: about 70% less CPU per request, over 80% less memory, and median time to first token down about 20% — with no downtime and no feature freeze. API traffic had grown roughly 1,800-fold from early 2024 to fall 2026.
